## Why

The library can refuse a leak and cannot deliver a secret. `slot-reads-secret-export`
(`lib/module.nix:238-247`) refuses a `reads` entry naming a secret export "outright, on every
machine and regardless of placement", so the one thing every real deployment needs — a database
password generated on one machine and opened by a service on another — is unexpressible. That is
the trigger `lib/excluded.nix:27-33` already records against `per` and `deploy`:

> the first value that is secret and has to reach a consumer on another machine, a database
> password being the case

The design corpus closes it in `notes/examples/secrets-per-instance/` of the sibling checkout: a
generator states a **cardinality** (`per`), a **delivery switch** (`deploy`), and the delivery set
is derived from **who declared a read**. Nothing else in the corpus can derive it — a routable
secret may legitimately go anywhere, so no bound on the value narrows the set, and `impl` runs
after wiring, so the set cannot be read out of the use site.

Two further defects fall out of the same gap and are fixed here rather than left:

- **A generated file's path is not unique on a machine.** `path = "/run/vars/${gen}/${fname}"`
  (`lib/resolve.nix:524`) carries no instance, so two instances of one module placed on one machine
  name one file. Delivery makes that collision reachable from a second direction: a machine can now
  receive one instance's secret while running another's.
- **The state of a value is keyed by machine.** `varsState.<machine>.<gen>.<file>`
  (`lib/resolve.nix:507`, `docs/README.md:178-180`) cannot describe a value that exists once for an
  instance: three placements would carry three answers about one value, free to disagree.

## What Changes

- **`vars.<gen>.per`** takes `"instance"` or `"placement"`, defaulting to `"placement"`. One value
  for the instance, or one per machine the owning member is placed on.
- **`vars.<gen>.deploy`** is a boolean defaulting to `true`. `per` says how many values exist;
  `deploy` says whether any machine receives bytes. A `deploy = false` generator's public files
  still travel as values in the plan, because a value in the plan needs no file on a machine.
- **`vars.<gen>.reads`** names sibling generators of the same module. A `per = "placement"`
  generator may read a `per = "instance"` one; the reverse is an arity mismatch and an error row.
- **A generated value becomes a plan entry of its own**: `<instance>:vars/<gen>` when
  `per = "instance"`, `<instance>:vars/<gen>@<machine>` when `per = "placement"`. It carries `per`,
  `deploy`, `delivery`, `deliveryDerivedFrom`, `reads`, `dependsOn`, `files` and its own `key`.
- **The delivery set is the owner plus the declared readers**: the machines the owning member is
  placed on, plus the machine of every entry whose `uses.<slot>.reads` names an export whose
  published value is a file of that generator. `deploy = false` makes it empty.
- **BREAKING — `slot-reads-secret-export` is deleted.** A slot may read a secret export, and the
  read is what puts the reader's machine in the delivery set. A consumer receives the export as the
  `secretRef` record its atom's type describes (`results.<slot>.<export>.path`), never as a bare
  string, so `env.X = results.db.password` fails loudly instead of exporting a path under the name
  of a password.
- **BREAKING — a generated file's path is `/run/vars/<instance>/<gen>/<file>`.** The instance
  segment is what makes the path unique on a machine that receives values it does not own.
- **BREAKING — `varsState` is keyed by vars entry key**:
  `varsState."<instance>:vars/<gen>[@<machine>]".<file> = { present, content }`. The identity of a
  value is the entry that names it, and the operator's store of generated bytes is keyed the same
  way as the thing it delivers.
- **The flakelet realiser stops refusing a delivered generated file.** Its refusal
  (`flakelet/read.nix:123-137`) is argued from having no assemble step, and it holds for a
  configuration file, whose bytes are staged from the store to a host path (`from != path`,
  `image/read.nix:226-233`). A generated file is its own source (`from == path`,
  `image/read.nix:234-240`): the delivery agent puts the bytes there before activation, so there is
  nothing to assemble and nothing to refuse.
- **New refusals**: a `per` outside the domain, two members of one instance claiming one generator
  name, a `reads` naming a sibling the module does not declare, a shared value reading a
  machine-specific one, a unit or configuration file opening the path of a file no machine receives,
  and a secret export backed by a generator no machine receives being read by a consumer.
- **A third end-to-end folder, `tests/e2e/secret-delivery/`**, three machines: the value is
  generated by the operator, delivered to the two machines the plan names, and the consumer
  authenticates against the provider over the network with it. The bystander holds nothing.

Not in this change, deliberately:

- **`locality` and `lifecycle`.** They remain excluded (`lib/excluded.nix:18-25`). Their absence is
  what makes the corpus's private-half refusal inexpressible here, so under this change a consumer
  that names a private half in `reads` **gets it delivered**. That is stated in the spec rather than
  hidden: the change that adds `locality` is the change that can cap an atom at machine-local and
  refuse the read.
- **File ownership and posture.** The corpus carries `files.<n>.owner` (binary-caches) and a
  `posture` marker for a rootless machine (secrets-per-instance). Both need a machine `class` field
  the registry does not have (`lib/resolve.nix:42-48`). The agent writes root-owned `0400`, which is
  what the profiles this repository realises can read.
- **Rotation, revocation lag and `producer`.** Rotating bytes moves no plan field, because bytes are
  not in the plan; what a rotation has to restart is the reload-versus-restart question, and it is
  not this change.
- **`state.per`.** The same keyword on a different declaration, which `declare-service-state` owns.

## Capabilities

### New Capabilities

- `planner/secret-delivery`: a generated value's cardinality, whether any machine receives it, the
  siblings it reads, the delivery set derived from declared reads, and every way each is refused.

### Modified Capabilities

- `planner/typed-edge`: a slot may read a secret export; the read decides delivery instead of being
  refused.
- `planner/plan-artifact`: a generated value is an entry of the plan with its own key; a generated
  file's path names its instance; the state the planner is told is keyed by entry.
- `realiser/flakelet-artifact`: an entry shown a delivered generated file is built rather than
  refused; a staged configuration file is still refused.
- `delivery/real-cluster`: a delivery moves generated bytes as well as store objects, and the
  machine layer proves the set the plan named is the set that received them.
