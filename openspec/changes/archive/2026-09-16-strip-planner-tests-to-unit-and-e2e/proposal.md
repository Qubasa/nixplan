## Why

`tests/` is 13,301 lines across five test technologies — nix-unit suites, pytest over serialised JSON, pytest over built bytes, a NixOS VM test, and a rookery cluster — and a reader cannot tell from a directory which of them owns a claim. `prove-plan-on-real-machines` added the fifth without removing any of the four it superseded, so the tree now asserts the same behaviour in two and three places at once:

- `tests/nixos/flakelet.nix` (243 lines, `checks.planner-flakelet-vm`) has 9 subtests. Seven are already observed on real rookery machines and two of those strictly more strongly — the VM asserts reachability on one machine, the cluster asserts it as traffic between two (`tests/python/test_cluster.py:361-365`), and the VM asserts one reboot where the cluster reboots both and re-proves the wire (`:480-496`). Its own guest is handed every store path at image-build time via `virtualisation.additionalPaths` (`tests/nixos/flakelet.nix:141-147`), which is the exact defect the previous change exists to fix and named in as many words (`prove-plan-on-real-machines/proposal.md:3-8`).
- `tests/python/test_cluster_offline.py` (170 lines, 12 tests): seven make a claim `test_cluster.py` makes against booted machines. Five are unit tests of `cluster/delivery.py`'s pure functions, which is a different subject wearing the same file name.
- `tests/python/test_image.py` (399 lines, 20 tests) drives **stub** `portablectl` and `systemctl` shell scripts it writes itself (`:31-40`). `tests/nixos/flakelet.nix:3-5` already names those stubs as the thing a real machine replaces. The portable-image realiser therefore has 1,022 lines of nix-unit plus 399 lines of pytest and zero machine-level evidence.
- `tests/python/test_flakelet.py` (217 lines, 12 tests): four are re-observed live by `test_cluster.py:332-339,422-477`.

The second cost is a serialisation layer that exists only so Python can assert facts Nix already holds. `tests/scenarios.nix` discovers `tests/scenarios/<name>/`, `flake-module.nix:79-99` serialises each to a `linkFarm` of JSON, `tests/python/conftest.py` loads it, `tests/python/plan.py` re-types it (241 lines of dataclasses over a document `mkPlan` returned typed), and ten tests then assert on it — of which `test_shared_postgres.py` (7) and `test_two_readers_one_database.py` (3) are named by **no** specification at all. `tests/python/golden.py` (229) plus `test_golden.py` (104) plus `tests/regenerate.py` (62) are a second traversal of the same shape, needed only because the committed fixture carries prose the plan does not.

The third cost is the cross-walk. `tests/mapping.nix` is 1,033 lines of hand-written table from specification headings to test names, enforced by `tests/suites/coverage.nix` (331 lines) which resolves an entry by grepping the test's own source text for `class X`, `def y(` or `subtest("z")` (`coverage.nix:183-215`). It is 1,364 lines — larger than any suite it indexes — it breaks on a rename or a reformat with no behavioural change, and it covers only 13 of the 25 `spec.md` files in the repository, so the guarantee it appears to give is partial. The table is also unnecessary: every test in the tree is **already** named after the scenario it observes. `#### Scenario: The machine holds what the artifact names` is `test_the_machine_holds_what_the_artifact_names`; `#### Scenario: A service publishes its own endpoint` is `testAServicePublishesItsOwnEndpoint`. A table that restates a mechanical function of the heading can be replaced by the function.

## What Changes

- **BREAKING: two test layers, and only two.** `tests/` becomes `tests/unit/` — nix-unit over the library and the two realisers' pure reading functions, in-eval, no Python and no serialisation — and `tests/e2e/<name>/` — one folder per end-to-end test, on real machines. Every other technology is removed. A reader answers "where is this asserted" from the directory name.
- **BREAKING: each e2e folder is self-contained.** `tests/e2e/<name>/` holds the interfaces, modules, machine registry, instances, the `artifacts.nix` that realises them and the `test_<name>.py` that observes them. `tests/scenarios/` and `tests/python/` both disappear as concepts: a configuration under test is not a corpus a separate suite reads, it is the fixture of the one test that reads it. Only what every e2e shares — the rookery runner, the delivery driver, the guest image — stays at `tests/e2e/`.
- **A second e2e replaces the stubbed image check**: `tests/e2e/portable-image/` delivers a planner-built portable-service image to a booted machine and runs the realiser's own `bin/attach` there (`image/default.nix:174-191`), so `portablectl attach --profile=<profile>` and `systemctl start` are the real binaries on a real machine, the confinement profile is one systemd enforces, and `bin/detach` is observed to leave the host files it was shown. `test_image.py` and its stubs are deleted; `tests/unit/image.nix` keeps only what a machine cannot show — the build-time refusals and byte-identical rebuild.
- **BREAKING: the specification cross-walk is derived, not committed.** `tests/mapping.nix` (1,033 lines) is deleted. A `#### Scenario:` heading names its test by construction: `test_<snake_case>` for an e2e, `test<CamelCase>` for a unit test. Coverage becomes a set difference between the headings and the test names that exist, plus one short `tests/omissions.nix` mapping a heading to the reason it has no test. A scenario asserted in both layers is impossible to express, which is what `add-scenario-test-harness`'s own requirement *"A behaviour SHALL NOT be asserted in both layers"* asks for and the table could not enforce.
- **Deleted outright** (4,893 lines): `tests/nixos/`, `tests/scenarios/`, `tests/scenarios.nix`, `tests/mapping.nix`, `tests/suites/coverage.nix`, `tests/suites/source.nix`, `tests/regenerate.py`, `tests/python/{conftest,plan,golden,test_artifact,test_golden,test_shared_postgres,test_two_readers_one_database,test_image,test_flakelet,test_cluster_offline}.py`, `image/check.nix`, `flakelet/check.nix`.
- **Ten scenario claims move in-eval.** The plan-level facts `test_shared_postgres.py` and `test_two_readers_one_database.py` assert — a DSN's provenance, disjoint `read_by` sets, a cross-machine `reach`, a `dependsOn` carrying only the machine — become nix-unit assertions on `mkPlan` output directly, with no JSON in between. The golden comparison joins them: the committed fixture stops carrying prose keys, so `fixtures/minimal-typed-edge/plan/backup.json` is compared with `==` in-eval and regenerated by `nix eval --json .#planner.worked.plan | jq -S . > …` rather than by a 62-line script sharing a 229-line traversal.
- **`suites/source.nix` goes.** Its three tests pin the exact 11-filename list of `lib/` (`:120-137`) and scrape row identifiers out of library source with a line regex (`:81-105`). The one claim worth keeping — the library raises nowhere — becomes a single assertion in `tests/unit/diagnostics.nix`, which is where totality is already asserted.
- **Checks collapse from nine to five**: `planner-tests`, `planner-perf`, `planner-perf-checker`, `planner-python`, and `planner-delivery` (the delivery driver's pure functions, which is what `planner-cluster-offline` honestly was once its seven duplicated tests are removed). `planner-scenarios`, `planner-images`, `planner-flakelet`, `planner-flakelet-vm` and `planner-cluster-offline` are removed, as are `packages.planner-scenarios-json`, `packages.planner-images` and `packages.planner-flakelet-artifact`.
- **One e2e entry point, two suites**: `nix run .#planner-e2e` runs every `tests/e2e/*/test_*.py`; `nix run .#planner-e2e -- wired-pair` runs one folder. `apps.planner-cluster` is renamed with it.

## Capabilities

### New Capabilities

- `tooling/test-layers`: what a planner test is. That there are exactly two layers and what decides which one a claim belongs to; that an e2e test's fixture lives in the e2e test's own directory; that a specification scenario's test name is a function of its heading rather than a committed table; and that a behaviour asserted on a real machine is not also asserted against a double.

### Modified Capabilities

- `delivery/real-cluster`: gains the portable-service-image realiser as a second delivery shape — what attaching a built image on a real machine consists of, that the confinement profile is enforced by the machine's own service manager, and what detaching leaves behind. Written as a delta under `specs/delivery/real-cluster/` because `openspec/specs/` is empty and the capability exists only in the unarchived `prove-plan-on-real-machines` change.
- `tooling/nix-unit-suite`: *Every spec scenario maps to a named test* is restated. The mapping is a derivation from the heading rather than a committed table, and a scenario with no test is a named omission rather than a table row.

### Removed Capabilities

- `tooling/scenario-suite`: the whole capability. Its subject — a committed configuration corpus, a serialised artifact a Python suite reads, and a two-layer rule policed by prose — is replaced by `tooling/test-layers`, in which a configuration under test is a directory belonging to one e2e test and there is no serialised corpus to read.

## Impact

- `tests/`: 4,161 lines deleted outright and 1,022 shrunk to a few hundred, against roughly 800 added for the new end-to-end test, the layer checks and the derived cross-walk — 13,301 lines to roughly 9,300, with `tests/e2e/portable-image/` the only directory that grows. `suites/` becomes `unit/`; `python/`, `scenarios/`, `nixos/`, `fixtures/`, `mapping.nix`, `scenarios.nix` and `regenerate.py` are gone or absorbed.
- `cluster/`: becomes `tests/e2e/`. `runner.py`, `delivery.py` and `image.nix` (the guest) stay at that root as the shared harness; `deployment/` and `artifacts.nix` move into `tests/e2e/wired-pair/` beside the test that uses them.
- `image/` and `flakelet/`: `check.nix` deleted from each (424 + 308 lines); `read.nix` and `default.nix` unchanged. No realiser behaviour changes.
- `flake-module.nix`: 498 lines to under 340. Four checks, three packages and five let-bound fixture builders removed; `apps.planner-cluster` becomes `apps.planner-e2e`.
- `docs/`: `tooling.md`'s per-row/scenario/layer sections and 14-row suite table, `cluster.md`'s suite paths, and the `tests/…` paths quoted in `README.md`, `authoring.md`, `diagnostics.md`, `plan.md` and `flakelet.md` all follow.
- `fixtures/minimal-typed-edge/plan/backup.json`: regenerated without prose keys. `plan/diagnostics.txt` unchanged.
- `openspec/changes/add-scenario-test-harness/`: its capability is removed by this change's delta. The change itself is left in place, unarchived, as the record of why the corpus existed.
- `flake.nix`: unchanged apart from `devShells.default`'s `inputsFrom`, which names `config.devShells.planner`.
- `lib/` and `perf/`: unchanged. No library behaviour is touched by this change, and `perf/budgets.json` is not re-measured.
