## Context

See proposal.md — Why. What follows is only what the approach has to work around, measured rather than assumed.

- **Nothing in the tree is source-filtered.** Every input to every check is a bare path literal (`${./tests}`, `${./tests/python}`, `${./cluster}`) or `plannerSrc = ./.`; `lib.fileset`, `cleanSource` and `filterSource` appear nowhere under `pkgs/planner`. A directory move is therefore a rename of path literals at `flake-module.nix:14,17,50,227,260,377,405,426,445,461-462` and nothing more.
- **The four pytest checks work only because everything lands in one flat directory.** Each does `cp ${./tests/python}/*.py <build dir>` and runs pytest there (`flake-module.nix:377,404,424,445,464`), because `test_*.py` import `plan`, `golden`, `conftest` and `delivery` as top-level modules. `cluster/delivery.py` is copied in beside them for exactly this reason (`flake-module.nix:374-376`). Per-folder e2e tests need `PYTHONPATH`, not a flat copy.
- **`conftest.py` makes the corpus mandatory for every file in the directory.** Its session `artifact` fixture reads `$PLANNER_SCENARIOS` and its autouse `_every_scenario_is_read` fails when a scenario directory no test named (`conftest.py:164-173`). Four suites already shadow the fixture name `artifact` to escape it (`test_cluster.py:105-115`, `test_cluster_offline.py:35-41`, `test_flakelet.py:35-40`, `test_image.py:44-49`). The shadowing is the measurement that says the corpus is not a shared fixture, it is one test's fixture wearing a session scope.
- **`cluster/deployment/` and `tests/scenarios/<name>/` already have the same shape.** Both glue files open with the identical sentence — "The only glue: close the package strings, import this directory's own interfaces, modules and deployment, and hand `mkPlan` its arguments" (`cluster/deployment/default.nix:1-2`, `tests/scenarios/shared-postgres/scenario.nix:1-2`) — and both build the same `args` with the same `sources` convention. This was deliberate (`prove-plan-on-real-machines/tasks.md:71`). Only the signature differs: `{ planner, packages }` against `{ planner, folder }`, because `scenarios.nix:24-40` hands the discovered folder in and cannot hand real store paths in.
- **`coverage.nix` resolves an external by reading test source as text.** `sourceOf` is `readFile (testsRoot + "/${rel}")` guarded by `match "[a-z0-9_/-]+\\.(py|nix)"` (`coverage.nix:158-177`) and existence is `hasInfix "def <name>("`, `hasInfix "class <C>"` or `hasInfix "subtest(\"<name>\")"` (`:183-215`). `testsRoot = ../.`. So a nested path like `e2e/wired-pair/test_wired_pair.py` already resolves; a path outside `tests/` does not.
- **`coverage.nix` enumerates its spec files rather than discovering them** (`:52-90`, with the reason in the file: "Named here rather than derived from the mapping, so a file the mapping forgot entirely is a failure rather than a silence"). It reads 13 of the 25 `spec.md` files in the repository; the other 12 are unenforced, and one of those 12 is `tooling/scenario-suite`, the specification of the corpus this change removes. Its staleness today is silent.
- **The realiser already carries the attach path a machine runs.** `image/default.nix:174-191` writes `bin/attach`: preamble, architecture and service-manager guards, host-file guards, configuration-file assembly, then `portablectl attach --profile=<profile> <raw>/<image>` and `systemctl start <units>`. `bin/detach` (`:196-203`) stops the units, detaches, and removes only the staging directory it created. `PORTABLE_PLANNER_ROOT` prefixes host state so the assembly can be staged elsewhere (`:96-99`). An e2e does not need to re-implement attaching; it needs a machine to run that script on.
- **`test_cluster.py` is already named after its specification.** Eighteen tests, one per `#### Scenario:` of `delivery/real-cluster/spec.md`, each name the heading in snake case. The unit suites do the same in camel case (`testAServicePublishesItsOwnEndpoint` for `#### Scenario: A service publishes its own endpoint`). `mapping.nix` restates that correspondence in 1,033 lines.
- **`nix flake check` cannot boot a cluster.** A build sandbox has neither `/dev/net/tun` nor `/dev/vhost-vsock` and cannot ask the daemon whether a path is valid (`prove-plan-on-real-machines/design.md` D2). Rookery is also private and resolved at run time from `$ROOKERY_FLAKE`, so no e2e can be a check. This is unchanged by this design and constrains where evidence can live.

## Goals / Non-Goals

**Goals:**

- A reader who wants to know where a claim is asserted answers it from a directory name, in two guesses at most.
- A reader who opens an e2e folder sees everything that test needs, with no upward reference except the shared harness.
- Deleting a test is a two-line edit, not a hunt through a 1,033-line table.
- Every claim that a machine can falsify is falsified by a machine, once.
- The line count goes down. Any step of this change that adds net lines outside `tests/e2e/portable-image/` is a step that has gone wrong.

**Non-Goals:**

- Any change to `lib/`, `image/read.nix`, `image/default.nix`, `flakelet/read.nix` or `flakelet/default.nix`. No realiser and no library behaviour moves. If a deletion appears to require one, the deletion is wrong.
- Re-measuring `perf/budgets.json`. The measured evaluation reads `lib/` and the worked fixture (`perf/measure.sh`), neither of which changes.
- Making an e2e runnable inside `nix flake check`. Not possible (Context); pretending otherwise produces a check one machine can run.
- A third layer. "Integration" is the name this tree gave to the place its doubles live, and reintroducing it would reintroduce them.
- Proving rookery, or changing how it is resolved. `$ROOKERY_FLAKE` and the run-time resolution stay exactly as `prove-plan-on-real-machines` left them.

## Decisions

**D1. Two layers, and the directory is the layer.** `tests/unit/` is nix-unit, in-eval, over `lib/` and the two realisers' `read.nix`; `tests/e2e/<name>/` is pytest against real machines under rookery. There is no third place, and a claim's layer is decided by one question: can a machine falsify it? A rendered `[Install]` section and a build-time refusal cannot — the first is a fact about text a machine would have to be handed, the second is a fact about an evaluation that never produces bytes — so both are unit. A unit that becomes active and answers a request can be, so it is e2e. The alternative considered was keeping the current three technologies and only deleting the duplicates; rejected because the duplication is a symptom of a middle layer whose defining property is that its participants are doubles (`test_image.py:31-40` writes its own `portablectl`), and a middle layer left standing refills.

**D2. An e2e folder owns its fixture; the harness is shared and is the only upward reference.** `tests/e2e/<name>/` holds `interfaces/`, `modules/`, `deployment/{machines,instances}.nix`, `artifacts.nix` and `test_<name>.py`. `tests/e2e/` holds `runner.py`, `delivery.py` and `guest.nix` — the rookery entry point, the delivery driver and the NixOS configuration both guests boot. The line where sharing stops is "would a second e2e want a different one": a different deployment, yes, always; a different 2.2 GB guest image, no, and paying two boots and two image builds for that would be a cost with no observation behind it. `guest.nix` therefore grows what the second e2e needs, with the same assertion discipline it already carries (`cluster/image.nix:38-100`). The alternative — a guest per folder — was rejected on cost, not on taste: `nix build .#planner-cluster-image` is 2.2 GB (`prove-plan-on-real-machines/tasks.md:59`).

**D3. The cross-walk is derived from the heading. `mapping.nix` is deleted.** One function turns `#### Scenario: The machine holds what the artifact names` into a word list, and two joins turn that list into the two spellings a test can have: `test_the_machine_holds_what_the_artifact_names` for pytest and `testTheMachineHoldsWhatTheArtifactNames` for nix-unit. Coverage is then a set difference between every scenario heading and every test name that exists, where the pytest names are **discovered** by `readDir` over `tests/e2e/*/test_*.py` rather than enumerated. Three consequences, each a deletion:

  - `### Requirement:` headings stop needing entries. A requirement is a grouping; only its scenarios are observations.
  - The 1,000-odd derivable rows disappear. What is left is the residue a derivation cannot produce, in one attrset in the same file: `omitted = { "<heading>" = "<reason>"; }` for a scenario deliberately unobserved, and `aliased = { "<heading>" = "<the test name that observes it>"; }` for the case that actually exists — two capabilities describing one behaviour in different words, such as `realiser/flakelet-artifact`'s `#### Scenario: The service is reachable` and `delivery/real-cluster`'s `#### Scenario: The consumer reaches the producer`. Both entries are prose a reviewer reads; neither is a row a rename breaks.
  - A name present in both layers is a failure, not a silence. `add-scenario-test-harness`'s own requirement — "A behaviour SHALL NOT be asserted in both layers" — was previously policed by prose and by an author's judgement. A derived name makes double-assertion a collision the check reports.

  The alternative considered was shrinking `mapping.nix` while keeping it. Rejected: a table that restates a function of its key is the defect, and 300 rows are as unmaintainable as 1,000 for the same reason — they can drift from what they describe, and only the table's author notices.

**D4. The portable-image e2e runs the realiser's own `bin/attach`, not a re-implementation.** The image artifact is delivered to a booted machine with the same `nix copy --to ssh://root@<the plan's address>` the wired-pair e2e uses (`delivery.py:224-232`), and the machine then executes `<artifact>/bin/attach`. This is the only honest form: a test that reconstructs `portablectl attach --profile=…` in Python asserts its own reconstruction, which is what `test_image.py` does today with a stub. Running the shipped script means the confinement profile is the one systemd applies, the architecture and service-manager guards (`image/default.nix:152-162`) are the ones an operator hits, and `bin/detach` is observed to remove the staging directory and nothing else. What stays in `tests/unit/image.nix` is what no machine can show: the four build-time refusals, and that a rebuild is byte-identical.

**D5. `checks.planner-cluster-offline` becomes `checks.planner-delivery`, holding only what it honestly was.** Seven of its twelve tests assert what booted machines assert; those go. The five that remain — `placed_key` resolution, the address read off a machine record, the refusal for a machine with no address, `NIX_SSHOPTS` carrying the key and no host file, the service name read off the artifact — are unit tests of pure functions in `delivery.py`, and pure functions are testable in a sandbox. Keeping them as a check named after the driver is not a hedge against the e2e being unrunnable in CI; it is the same layer rule as everywhere else, applied to Python. `prove-plan-on-real-machines` design D3 kept the whole file so that `nix flake check` would still fail on a cluster regression; this change accepts that it no longer will, because the alternative is asserting a machine's behaviour against bytes and calling the result coverage.

**D6. The golden fixture stops carrying prose, and the comparison moves in-eval.** `fixtures/minimal-typed-edge/plan/backup.json` is compared with `fromJSON (readFile …) == workedPlan` in `tests/unit/plan.nix`. Regeneration becomes `nix eval --json .#planner.worked.plan | jq -S . > fixtures/minimal-typed-edge/plan/backup.json`. This deletes `golden.py` (229), `test_golden.py` (104) and `regenerate.py` (62), and the reason all three existed: the fixture carries `note` and `why` keys the plan does not, so comparison needed a prose-aware traversal at every depth (`golden.py:16,26`) and regeneration needed to re-inject prose it had collected (`:133-172`). Nix's `==` reports which attribute path differs when a `nix-unit` test fails, so the "names the field that differs" requirement survives without the traversal. The prose moves to `plan/README.md`, where prose belongs and where no test has to step around it. The alternative — keeping the traversal in Nix — was rejected: it is 229 lines of machinery to hold two keys that should not be in the document.

**D7. The ten scenario-corpus claims become nix-unit assertions on `mkPlan` output.** `test_shared_postgres.py` and `test_two_readers_one_database.py` assert plan-level facts — a DSN's `source == "deployment"`, disjoint `read_by` sets, a cross-machine `reach = "one"`, a `dependsOn` carrying only the machine. Every one of those is an attribute of the value `mkPlan` returns, and the only reason Python was reading it was the serialisation layer. Asserting them in-eval deletes that layer entire: `scenarios.nix`, the `linkFarm` (`flake-module.nix:79-99`), `conftest.py`, `plan.py`'s 241 lines of dataclasses re-typing a typed document, `test_artifact.py` (which tests the loader, a thing that will not exist), `checks.planner-scenarios` and `packages.planner-scenarios-json`. The two configuration directories go with it: their value was being a committed configuration in a real shape, and an e2e folder is a committed configuration in a real shape that a machine also runs.

**D8. The NixOS VM test is deleted and its two genuinely-unobserved claims are re-observed, one by a new entry and one as a named omission.** Of nine subtests, seven are already observed on real machines. The residue:

  - **The scheduled-unit rule** — "a scheduled unit is not fired by deploying it" — is not observed by the cluster, because `cluster/deployment/` declares no scheduled entry. It gets one: a third entry in `tests/e2e/wired-pair/` with a `schedule`, so one boot observes that the timer is enabled and the service did not run. A new folder for this would be a second boot for one observation.
  - **The declarative activation path** — `services.flakelets.services.<name>.prebuilt` at boot — is not observed and cannot be, because the cluster guest asserts the opposite: `services = {}` with the endpoint enabled (`cluster/image.nix:80-83`), which is what makes "the machines are not told the answer" checkable. It becomes an omission whose reason says so. Asserting it would require a guest that carries the artifact in its own closure, which is the defect this whole line of work removed.
  - **The rollback provenance field** `status["changed"]["by"] == { kind = "rollback"; from = 2; }` is a field of the endpoint's report, and the e2e already reads that report (`delivery.py:270-284`). It is added to the existing rollback observation rather than kept as a reason to keep a VM.

**D9. `suites/source.nix` is deleted; one of its three claims survives in `tests/unit/diagnostics.nix`.** "The library raises nowhere" is load-bearing — totality is the planner's central promise and `diagnostics.nix` is where it is already asserted — so the line grep for `throw`/`abort`/`assert `/`.check ` moves there, next to the `tryEval (deepSeq …)` property it belongs with. The other two do not survive: pinning the exact eleven-filename list of `lib/` (`source.nix:120-137`) fails on a rename with no behavioural change, and scraping row identifiers out of library source with `match ".*(id|excluded|unknown|missingType) [?=] \"([a-z][a-z0-9-]*)\"[,;].*"` (`:81-85`) to compare against a markdown table couples a documentation table to a regex over source text. A documentation table that drifts is a documentation problem.

**D10. `tests/e2e/` stays under `tests/`.** The coverage check resolves a test file relative to one tests root (`coverage.nix:158`), and a single root is also what lets discovery be `readDir`. `e2e/` beside `tests/` was considered and rejected: it buys nothing and costs the check a second root to know about.

**D11. Each e2e folder is a pytest rootdir of its own, reached by `PYTHONPATH`, with no `conftest.py`.** The runner puts `tests/e2e/` on `PYTHONPATH` and invokes pytest on one folder or on all of them; a test imports the harness as `import delivery` because `tests/e2e/` is on the path, and imports nothing from a sibling folder. There is no `conftest.py` anywhere: the fixtures each e2e needs — its key directory, its cluster, its delivered state — are that e2e's, defined in its own file, which is what "self-contained" means when applied to pytest. The flat `cp *.py` copies disappear with the checks that used them.

**D12. `flake.planner.failures` and `report.nix` stay.** Twenty-six lines that answer red-or-green by `nix eval` with no build (`flake-module.nix:42-43`), which is the fastest loop in the repository and the one a reader of a failing suite reaches for first. It is the one piece of meta-machinery that pays for itself.

## Risks / Trade-offs

- **`nix flake check` loses every machine-level claim.** → Accepted, and named in D5 rather than mitigated. The claims do not disappear; they move to `nix run .#planner-e2e`, which is a command a human runs on a host with `/dev/kvm`, `/dev/net/tun` and `/dev/vhost-vsock`, documented in `docs/cluster.md`. The alternative kept a byte-level restatement of a machine's behaviour inside CI, which is the duplication this change exists to remove. `checks.planner-delivery` keeps the driver's pure half inside CI, so a regression in the addressing or the refusal still fails a build.
- **The derived cross-walk will report a set of mismatches the moment it lands**, because `mapping.nix` today maps some headings to differently-named tests and some to lists of them. → That set is the work, not a surprise: each mismatch is a rename to the heading's slug, an `aliased` entry when two capabilities describe one behaviour, or an `omitted` entry with a reason. The migration lands the check before any deletion, so the list is enumerated once and closed deliberately.
- **A scenario heading edit now renames a test.** → That is the intended coupling and the reason the table is going: today a heading edit and a test rename can drift and only `mapping.nix`'s author notices. The cost is that rewording a heading is a two-file edit; the benefit is that it cannot be a one-file edit that silently loses evidence.
- **`tests/e2e/portable-image/` is the one net addition.** Its guest needs `systemd-portabled`, and a portable service's confinement profile can fail for reasons that are systemd's rather than the planner's. → The guest invariant is asserted in `guest.nix` the way the others are, so a missing `portablectl` fails the build rather than a boot; and the realiser's own guards (`image/default.nix:152-162`) fail with a named message before anything is attached.
- **Deleting `tooling/scenario-suite` removes a specification whose requirements are true of the code today.** → It is removed because its subject is removed, with the reason and the migration written into the delta. The change that introduced it stays unarchived in `openspec/changes/add-scenario-test-harness/` as the record of why a committed configuration corpus was worth having, which is the part this change keeps — an e2e folder *is* that corpus, with a machine attached.
- **One guest image serves two e2e folders (D2), so a change one needs can break the other.** → Every invariant in `guest.nix` is an assertion with a message naming what depends on it, which is already how that file works (`cluster/image.nix:38-100`); a removal fails `nix build` rather than a boot. The coupling is visible in one file of ~250 lines.

## Migration Plan

Five phases. `nix flake check` and `nix run .#planner-e2e` are both green at every phase boundary; no phase leaves a claim unasserted with the intention of restoring it in the next.

1. **Move, do not delete.** `cluster/` becomes `tests/e2e/` with `deployment/` and `artifacts.nix` moved into `tests/e2e/wired-pair/`; `tests/suites/` becomes `tests/unit/`; `tests/fixtures/worked.nix` and `tests/support.nix` move into `tests/unit/`. `mapping.nix` external strings and `coverage.nix`'s `testsRoot` follow the paths. `apps.planner-cluster` becomes `apps.planner-e2e` and gains the per-folder argument. Nothing is deleted and no claim moves layer, so the diff is reviewable as a rename.
2. **Replace the cross-walk.** Land the derived check in `tests/unit/coverage.nix`, delete `mapping.nix` and the old `coverage.nix`, and close the reported mismatch list — renames to heading slugs, `aliased` entries for cross-capability duplicates, `omitted` entries with reasons. This phase's evidence is the check reporting an empty difference over the tree as it stands before any deletion.
3. **Delete the superseded surfaces and land their residue.** `tests/nixos/`, `test_image.py`, `test_flakelet.py`, the seven duplicated tests of `test_cluster_offline.py`, the scenario corpus and its serialisation layer, `suites/source.nix`, `image/check.nix`, `flakelet/check.nix`, and the checks and packages that build them. In the same phase: the residue claims land in `tests/unit/` (D6, D7, D9), the scheduled entry and the rollback-provenance assertion land in `tests/e2e/wired-pair/` (D8), and the remaining five delivery tests become `checks.planner-delivery` (D5).
4. **Add the portable-image e2e.** `tests/e2e/portable-image/` with its own deployment and test; `guest.nix` gains `systemd-portabled` and the assertion that says why. `tests/unit/image.nix` shrinks to the refusals and the byte-identical rebuild.
5. **Documentation and the flake module.** `docs/tooling.md`'s layer, suite-table and scenario sections; `docs/cluster.md`'s paths; the `tests/…` paths quoted in `README.md`, `authoring.md`, `diagnostics.md`, `plan.md`, `flakelet.md`. `flake-module.nix` loses the removed checks, packages and the second devShell's reason to name a suite file.

Rollback is per phase: each is a commit whose revert restores a tree that was green. Phase 3 is the only one that destroys evidence, and it lands after phase 2 has made the evidence's absence a build failure rather than a silence.
