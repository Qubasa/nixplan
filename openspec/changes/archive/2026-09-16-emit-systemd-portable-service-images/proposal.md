## Why

A systemd portable service is a directory tree or DDI carrying an operating-system identity file, unit files under `/etc/systemd/system/`, and the binaries those units name; `portablectl attach` then binds it into the host. **Today's planner cannot produce one, and the gap is not effort — it is six missing facts.** A plan entry records `units.<name>.command` and nothing else (`lib/plan.nix:327`), so there is no unit type, no ordering, no user and no hardening to render into a unit file; `env` is merged per entry rather than per unit (`lib/plan.nix:92-114`), so two units of one service that need different environments are an error row (`unit-environment-conflict`, `lib/plan.nix:108`) instead of two units; a configuration file is recorded as a content hash with neither the bytes nor a path to them (`lib/plan.nix:294`), so nothing downstream can write the file the image is supposed to carry; the machine registry admits exactly `address` and `tags` (`lib/resolve.nix:44-47`) while a module's `platforms` is validated and then consumed by nothing (`lib/module.nix:365-373`), so neither a target architecture nor a target service manager is derivable; the closure is a hand-rolled regex over two of an entry's fields (`lib/util.nix:74-80`, `lib/plan.nix:328`) whose pattern hardcodes `/nix/store` and accepts hash characters Nix's base-32 alphabet does not contain, so the list an image would be populated from is both incomplete and unsound; and `mkPlan` realises nothing by contract (`lib/default.nix:1-3`, `lib/plan.nix:5-6`) with purity asserted by test (`tests/suites/perf.nix:45-53,111-126`), so the image cannot be built inside the planner at all.

Worse than each absence is the silence around it. The declaration half of a module is allow-listed and refuses an unknown key with a row (`lib/module.nix:20-27,360`), but the implementation half is not: `mkPlacement` reads `impl.units or { }` and `impl.configData or { }` with no key check (`lib/resolve.nix:397,421`), and `placedEntry` projects a unit down to `{ command }` (`lib/plan.nix:327`). An author who writes `units.web.user = "myapp"` today gets a plan that silently omits it — the one failure mode this library was built to refuse.

## What Changes

### The unit vocabulary is typed, and so is every backend's extension of it

- A unit's fields are declared with types rather than by convention. The portable vocabulary — `command`, `env`, `after`, `requires`, `user`, `oneShot`, `remainAfterExit`, `schedule`, `timeout`, `stopCommand`, `reloadCommand` — is the set the design corpus already writes into its committed plan fixtures (`examples/firewall/plan/backup.json:84-93,144-160`, `examples/quiesce-group/plan/participants.json:180-205`) and which today's library drops. Each field carries a type, and a value failing it is a row, exactly as an export failing its atom's type is `export-type-mismatch` today.
- A unit **extension** is a typed value naming one backend and the fields it adds — `planner.unitExtension { backend = "systemd"; name; fields; }` — identified by the value a module imported, the way an interface is (`lib/interface.nix:36-44`). There is no untyped passthrough: a systemd-only field is as statically typed as a portable one, and it is refused with a row when it is misspelled, mistyped, or applied to a unit whose target does not run that backend.
- A module learns its target from a new `impl` argument, so it can define the portable parts once and add extensions only where they apply: `impl = { target, ... }: { units.web = { … } // lib.optionalAttrs (target.serviceManager == "systemd") { extends = [ … ]; }; }`. The plan records extensions grouped by backend, so a renderer for another backend refuses knowingly rather than dropping fields.
- **BREAKING** the implementation half of a module is read the way the declaration half is. An unrecognised key under `impl`, under a unit, under a unit extension or under a configuration file becomes `implementation-unknown-key` rather than being discarded.
- **BREAKING** `env` moves to the unit. `units.<name>.env` is recorded per unit and the entry-level `env` becomes the intersection all units agree on. `unit-environment-conflict` (`lib/plan.nix:108`) is deleted: two units of one service disagreeing about a variable is the ordinary case for a portable service, not an error.

### The plan names bytes and never carries them

- A configuration file records `mode`, the units it reloads, and exactly one of two dispositions: `source`, a store path holding the rendered file; or `render`, an ordered list of public literal fragments and path references the machine concatenates. A store path can be copied out of the store with no evaluator and no daemon, which is the Disnix property — the plan is free of evaluation, not free of store paths.
- **No digest is ever taken over a value the plan does not itself carry.** A `render` list containing any reference records a structure hash over its fragments and reference paths, never a content hash over assembled bytes. `contentHash` survives only for a file that is entirely public literal text. This closes a hazard today's `contentHash = util.shortHash content` (`lib/plan.nix:294`) would acquire the moment a secret's bytes became reachable from `impl`.
- `reload` stops being every unit of the entry (`lib/plan.nix:270`) and becomes the units the module named.

### A machine declares what it is, and the plan records it in a form a builder can spend

- A machine declares `system` and `serviceManager`, and may declare a microarchitecture. The plan records a **reduced elaboration** of the platform — the JSON-safe projection of `lib.systems.elaborate` (`system`, `config`, `libc`, `useLLVM`, `linuxArch`, `parsed.cpu`, `parsed.kernel`, `parsed.abi`, and the codegen group `gcc`) — because the elaborated record itself carries functions and a plan carries none. The `is*` predicates are excluded: each is a function of `parsed`, so the projection is what a cross build spends and nothing derivable from it.
- A module's `platforms` stops being validated-and-dropped: a placement whose machine's system matches no entry is `placement-platform-mismatch`, and a unit extension whose backend is not the machine's `serviceManager` is `unit-extension-backend-mismatch`.

### The closure is declared, its pin is recorded, and the scanner becomes a verifier

- An entry's closure roots are **declared** by the module rather than inferred from its strings. The string scan survives only as a cross-check: a store path mentioned anywhere in the entry and absent from the declared roots is `closure-path-undeclared`, and a declared root mentioned nowhere is a warning. Inference cannot guarantee completeness; a declaration plus a contradiction check can.
- The scan stops hardcoding a store directory and stops accepting impossible hashes. `mkPlan` takes `storeDir`, defaulting to `builtins.storeDir`, and the recogniser is built from Nix's actual store-path grammar — a 32-character hash over the base-32 alphabet `0123456789abcdfghijklmnpqrsvwxyz`, which excludes `e`, `o`, `t` and `u` and which today's `[0-9a-z]{32}` (`lib/util.nix:79`) wrongly admits.
- The scan covers the whole entry, not `units` and `env` alone, so a store path named only by a configuration file or only by an export value is either declared or a row.
- **An entry records the pin its roots were built from, and the planner does not resolve pins.** A module declares a pin key and a locked record — source, revision, content hash, all literal strings — and a locked record naming no revision or no hash is an error row, because a pin that can resolve to different bytes on a later evaluation is what per-service pinning exists to refuse. The pin is a `keyInput`, so a re-pin re-keys exactly the entries whose bytes moved. **Resolution stays with `mana`** (`~/Projects/mana`), which already owns every part of it: `dependencies.<name>.url`, `shares` to put one nixpkgs across a whole tree, `pins` to protect a library's own version from a consumer's `shares`, narHash dedup and the documented precedence in `resolveNode`. So the planner holds no pin registry, no default and no override precedence — one nixpkgs for the fleet, several side by side, or every module on its author's pin are all `mana.nix` decisions, and whether two services share a dependency is answered by their pin keys being equal. The planner records a pin and never verifies it; confirming the bytes came from it is the build plane's job.

### The image is built outside the planner

- A new realiser consumes one plan entry and produces one portable-service image: the identity file, one rendered unit per unit the entry records, the declared closure copied in, and the `portablectl` attachment description with its confinement profile. Secrets and configuration files never enter the image; they are shown to it from the host at attach time, which is what keeps a configuration change a reload rather than a rebuild (`notes/clan-portable-services-design.md:2304-2309`).
- The design corpus records the terminology amendment. `notes/clan-portable-services-design.md:2341-2346` reserves "portable service" for the P4 module layer and names the unit format a **modular service**; this change makes the systemd portable-service image one *binding* of that vocabulary — the sibling of the launchd `lib.services.configure` path (`:2280-2282`) — and never the unit format, because macOS, rootless user systemd and embedded targets remain in charter (`:3604`).

## Capabilities

### New Capabilities

- `planner/unit-vocabulary`: the typed portable unit vocabulary, typed per-backend unit extensions, backend targeting from a module's implementation, per-unit environments, and the configuration-file record.
- `planner/machine-platform`: `system` and `serviceManager` on a machine, the reduced platform elaboration the plan records, `platforms` crossed against it, and the rows a mismatched placement or extension produces.
- `planner/closure-declaration`: declared closure roots, the pin they were built from and the rows an override or an underspecified pin produces, the configurable store directory, the store-path grammar, and the contradiction rows the string scan produces as a verifier.
- `realiser/portable-service-image`: the artifact built outside the planner from one plan entry — image layout, unit and extension rendering, closure population, attachment and profile, and what may never enter an image.

### Modified Capabilities

- `planner/plan-artifact`: the requirement "Values are recorded on the plane their use site implies" gains per-unit environments, the two configuration-file dispositions and the declared closure. The capability exists today only in the unarchived `implement-minimal-typed-edge` change, so this delta is written against that text.

## Impact

- **Library** — `lib/interface.nix`: the `unitExtension` constructor beside `interface`, sharing `atomRows`' type-and-key checking. `lib/atoms.nix`: the atom types the vocabulary needs beside `url` and `secretRef`. `lib/module.nix`: a typed units/extensions/configData reader, and the `implementation-unknown-key` dispatch mirroring `keyRow` (`:57-79`). `lib/resolve.nix`: `machineRegistryKeys` (`:44-47`) gains `system` and `serviceManager`; `implArgs` (`:383-389`) gains `target`; `mkPlacement` (`:351-423`) reads the implementation through the new reader; a platform check beside `placementRows` (`:236-272`). `lib/plan.nix`: `mergedEnv` (`:92-114`) becomes an intersection and loses its row; `configDataRecord` (`:262-299`) becomes the two-disposition record; `placedEntry` (`:311-377`) records the vocabulary, per-unit env, extensions, the platform record and the declared closure. `lib/util.nix`: `storePathsIn` (`:74-80`) is rebuilt from `storeDir` and the base-32 alphabet and demoted to a verifier. `lib/default.nix`: `mkPlan` (`:83-89`) gains `storeDir`.
- **New dependency** — `lib.systems.elaborate` from the pinned nixpkgs, for the platform record. It is pure Nix and produces no derivation; one elaboration per distinct `system` string, memoised, so the cost is bounded by the number of architectures in the fleet rather than the number of machines.
- **New source** — a realiser package outside `lib/`, since `mkPlan`'s purity is source- and test-enforced (`tests/suites/perf.nix:45-53,111-126`) and its argument and return sets are closed (`lib/default.nix:83-89,118-122`).
- **Keys** — `keyInput` (`lib/plan.nix:334-347`) gains the vocabulary, the per-unit environments, the extensions and the platform record; every entry in `fixtures/minimal-typed-edge/plan/backup.json` re-keys, and the fixture is regenerated with `python3 tests/regenerate.py`.
- **Tests** — `tests/suites/plan.nix` for the vocabulary, the two dispositions and the deleted conflict row; `tests/suites/interfaces.nix` for extension typing; `tests/suites/exclusions.nix` is untouched, because no construct is added to `excluded.constructs` and `testEveryExclusionTableRowIsCovered` (`:465-505`) hard-asserts that table's size; `tests/mapping.nix` gains one entry per new spec heading, or `tests/suites/coverage.nix` fails.
- **Docs** — `docs/authoring.md` (the implementation return shape at `:156-160`, the machine registry at `:250-260`), `docs/plan.md` (the entry field table at `:44-54`, the planes table at `:139-149`), `docs/diagnostics.md` (the new row ids, one deleted), `docs/README.md` (`:127-137` for `storeDir`, `:164-175` for `unitExtension`).
- **Design corpus** — `notes/clan-portable-services-design.md` §16.7 (`:2341-2346`) gains the amendment that a systemd portable-service image is a binding rather than the unit format.
- **Not changed** — interfaces, slots, wiring, reach, placement selectors, the diagnostics row shape, and the rule that a secret is a path reference whose bytes appear nowhere in the plan.
